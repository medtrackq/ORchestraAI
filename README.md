# ORchestraAI — ระบบนัดผ่าตัดอัจฉริยะ

ระบบจัดตารางห้องผ่าตัดแบบ Multi-Agent ที่ประสานทรัพยากร 3 ด้าน ได้แก่ **ทีมงาน**, **เครื่องมือ/CSSD** และ **ห้องผ่าตัด + เตียง PACU/ICU**
แล้วส่งให้ **Google OR-Tools CP-SAT** คำนวณตารางที่ไม่ชนกัน รองรับเคสฉุกเฉินแทรกและการผ่าตัดยืดเยื้อ (Ripple Effect)

## เข้าใช้งานผ่านเว็บ (Render)

repo มี `render.yaml` (Render Blueprint) สำหรับ deploy เว็บแอป `app/` เป็น service เดียว (หน้าเว็บ + API)

1. Render Dashboard → **New → Blueprint** → เลือก repo `medtrackq/ORchestraAI` (branch `main`) → **Apply**
2. รอ build เสร็จ (ครั้งแรกประมาณ 3-5 นาที) แล้วเปิด URL ของ service `orchestra-ai` (เช่น `https://orchestra-ai.onrender.com`)
3. ล็อกอินครั้งแรกด้วยบัญชีหลัก: ชื่อผู้ใช้ `orchestra` รหัสผ่านดูได้ที่ service → **Environment** → `APP_PASSWORD` (Render สุ่มให้ เปลี่ยนเองได้) แล้วสร้างบัญชีของแต่ละคนในแท็บ **ผู้ใช้**

หน้าเว็บ: ตารางทุกห้อง · จองผ่าตัด (Agent ตรวจเวลา + เสนอช่วงใหม่) · แทรกเคสฉุกเฉิน · ผ่าตัดเกินเวลา · ประวัติกิจกรรม/แจ้งเตือน · `/flow` หน้า Flow สาธิต · `/api/docs` เอกสาร API

ถ้าไม่ได้ตั้ง `DATABASE_URL` แอปจะใช้ข้อมูลจำลองในหน่วยความจำ (รีเซ็ตเมื่อ service restart) plan ฟรีของ Render จะหลับเมื่อไม่มีคนใช้ 15 นาที เปิดครั้งแรกหลังจากนั้นรอประมาณ 1 นาที

### บัญชีผู้ใช้และบทบาท

| บทบาท | ทำอะไรได้ | Agent ที่เกี่ยวข้อง |
|---|---|---|
| `admin` ผู้ดูแลระบบ | ทุกอย่าง + จัดการผู้ใช้ + ใส่ข้อมูลตัวอย่าง | — |
| `scheduler` ผู้จัดตาราง OR | จอง / ฉุกเฉิน / เกินเวลา ทุกเคส, อัปเดตเครื่องมือ, แก้ preference card, เห็นการแจ้งเตือนทั้งหมด | Master Orchestrator |
| `surgeon` ศัลยแพทย์ | จอง / ฉุกเฉิน / แจ้งเกินเวลา **เฉพาะเคสที่ตัวเองเป็นแพทย์หลัก** และแก้ preference card ของตัวเอง (ต้องผูกกับรายชื่อศัลยแพทย์) | Intake & Triage |
| `cssd` จ่ายกลาง | อัปเดตสถานะเครื่องมือและเวลาอบเสร็จ, ดูตาราง **ไม่เห็น HN/ชื่อผู้ป่วย** | Equipment & Inventory |
| `staff` วิสัญญี / พยาบาล | ดูตาราง, เห็นเคสของตัวเอง ("ของฉัน") และการแจ้งเตือนของตัวเอง | Staffing |

- admin สร้างบัญชีในแท็บ **ผู้ใช้** ระบบสุ่มรหัสชั่วคราวให้ (แสดงครั้งเดียว) ผู้ใช้ต้องตั้งรหัสใหม่เมื่อเข้าครั้งแรก
- รหัสผ่านเก็บแบบ scrypt hash · session เป็น cookie ที่เซ็นด้วย HMAC (HttpOnly, SameSite=Lax, Secure บน HTTPS) อายุ 12 ชั่วโมง · เปลี่ยนรหัส / เปลี่ยนบทบาท / ปิดบัญชี = ออกจากระบบทุกเครื่องทันที · **กดออกจากระบบ = cookie ใช้ไม่ได้อีก** (บัญชีในระบบ: ออกจากทุกเครื่อง) แม้มีคนคัดลอก cookie ไว้ (เครื่องใช้ร่วมในหอผู้ป่วย)
- ล็อกอินผิด 5 ครั้งใน 10 นาทีจากที่อยู่เดียว หรือ 20 ครั้งต่อชื่อผู้ใช้จากทุกที่ ถูกพัก 10 นาที · ทุกการล็อกอินใช้เวลาเท่ากัน (เดาไม่ได้ว่าชื่อผู้ใช้ไหนมีอยู่) · IP อ่านจาก `CF-Connecting-IP` ของ Cloudflare หน้า Render · การแก้ไขข้อมูลต้องเป็น JSON จากเว็บเดียวกัน (กัน CSRF)
- ควรตั้ง `SESSION_SECRET` (Render Blueprint สร้างให้อัตโนมัติ) · ถ้าไม่ตั้ง ระบบคำนวณกุญแจจาก `APP_PASSWORD` แบบช้า (scrypt) · หน้า ⚙ สถานะระบบเตือนเมื่อไม่ได้ตั้ง หรือ `APP_PASSWORD` สั้นกว่า 12 ตัว
- ทุกหน้ามี Content-Security-Policy, HSTS, X-Frame-Options และไม่ cache · ข้อมูลที่ส่งเข้ามาใหญ่เกิน 12 MB ถูกปฏิเสธ
- ทุกการเปลี่ยนแปลงบันทึกชื่อผู้ทำใน `orchestra_activity.actor`
- บัญชีหลักจาก `APP_USERNAME` / `APP_PASSWORD` ใช้ได้เสมอ (สำหรับเจ้าของระบบ) เปลี่ยนรหัสที่ Render
- **ยืนยันตัวตน 2 ชั้น** (หน้า `/security` ปุ่ม 🔐 ความปลอดภัย · ต้องรัน SQL ไฟล์ 018): หลังรหัสผ่าน กรอกรหัส 6 หลักจากแอป Google / Microsoft Authenticator (TOTP มาตรฐาน RFC 6238 รหัสเปลี่ยนทุก 30 วินาที ใช้ได้ครั้งเดียว ไม่ต้องส่ง SMS)
  - **บังคับบทบาท admin:** เข้าระบบแล้วถูกพาไปตั้งค่าก่อนใช้อย่างอื่น · บทบาทอื่นเปิดเองได้ · เปลี่ยนรายการบทบาทที่บังคับด้วย `TWO_FACTOR_ROLES` (เช่น `admin,scheduler` หรือ `none`) · โหมดข้อมูลจำลองไม่บังคับ
  - **รหัสสำรอง 10 รหัส** แสดงครั้งเดียว ใช้แทนรหัสจากแอปได้รหัสละครั้ง (เก็บเฉพาะ hash) · เปลี่ยนมือถือ: “ย้ายไปมือถือเครื่องใหม่” (ต้องใช้รหัสจากเครื่องเดิมหรือรหัสสำรอง) · มือถือหายและไม่มีรหัสสำรอง: admin กด **ล้าง 2 ชั้น** ในแท็บผู้ใช้
  - **บัญชีหลัก:** รหัสลับเก็บใน Render ชื่อ `APP_TOTP_SECRET` (ได้จากหน้า `/security`) เพื่อให้เข้าได้แม้ฐานข้อมูลมีปัญหา · ตั้งหรือเปลี่ยนค่า = ทุกเครื่องของบัญชีหลักออกจากระบบ · มือถือหาย: แก้หรือลบค่านี้ใน Render · ค่าผิดรูปแบบจะถูกเพิกเฉย (ไม่ล็อกเจ้าของออก) และหน้าสถานะเตือน

### Intake & Triage Agent

กล่องด้านบนของแท็บ **จองผ่าตัด** / **ฉุกเฉิน**: พิมพ์หรือกด 🎙️ พูดคำขอ เช่น *"หมอ Napat ขอผ่าตัดถุงน้ำดีส่องกล้อง HN 123456 พรุ่งนี้ 9 โมง เคสซับซ้อน"* แล้วกด **วิเคราะห์คำขอ**

- **อ่านคำขอ:** หาศัลยแพทย์ หัตถการ วันที่ เวลา ความซับซ้อน ICU ความเสี่ยงติดเชื้อ และ HN แล้วกรอกฟอร์มให้ (ทีมและเครื่องมือมาจาก preference card)
  - ถ้าตั้ง `ANTHROPIC_API_KEY` จะใช้ Claude (`INTAKE_MODEL`, ค่าเริ่มต้น `claude-opus-5-5`, ผลลัพธ์บังคับตาม JSON schema)
  - ถ้าไม่ตั้ง หรือเรียก Claude ไม่สำเร็จ จะใช้ตัวแยกคำแบบกฎภาษาไทย/อังกฤษ
- **ความเป็นส่วนตัว:** HN และตัวเลขยาวถูกปิดก่อนส่งให้ Claude · หัตถการและแพทย์ส่งเป็นรหัสสั้น (P1, S2) · ขอให้ไม่พิมพ์ชื่อผู้ป่วย · ปุ่มพูดใช้ระบบแปลงเสียงของเบราว์เซอร์ (Chrome ส่งเสียงไปที่ Google)
- **คัดแยกความเร่งด่วน:** Elective / Urgent / Emergency พร้อมเหตุผล · กฎคำสำคัญเป็นตาข่ายความปลอดภัย (ถ้ากฎพบคำบ่งชี้ฉุกเฉิน จะไม่ถูกลดระดับ) · เคสฉุกเฉินถูกส่งไปกรอกในแท็บฉุกเฉิน
- **พยากรณ์เวลาผ่าตัด** (`orchestra_engine/intake.py`):
  - ตั้งต้นจาก preference card (หรือเวลามาตรฐานของหัตถการ)
  - ถ่วงกับเวลาผ่าตัดจริงของแพทย์คนนั้นกับหัตถการนั้น (ค่าตั้งต้นมีน้ำหนักเท่า 3 เคส)
  - ถ้ายังไม่มีประวัติหัตถการนี้ ใช้ความเร็วของแพทย์จากหัตถการอื่น
  - คูณความซับซ้อน (ง่าย ×0.85 / ซับซ้อน ×1.3 — ค่าตั้งต้น ปรับได้)
  - แนะนำจองเผื่อให้ครอบคลุมราว 70% ของเคสที่ผ่านมา และแสดงคำอธิบายทุกขั้น
- **ประวัติผ่าตัดย้อนหลัง:** เคสที่นำเข้าจาก Excel (2 ปีล่าสุด) ถูกนับรวมกับเวลาจริงในระบบ ทั้งในการพยากรณ์และใน preference card (ดูหัวข้อ "ประวัติผ่าตัดย้อนหลังจาก Excel")
- **บันทึกเวลาจริง:** คลิกเคสในตาราง → *บันทึกเวลาจริง* (admin, ผู้จัดตาราง หรือคนในทีมของเคสนั้น) → เก็บใน `actual_start_time` / `actual_end_time` และระบบเรียนรู้ทันที
- **ข้อมูลตัวอย่าง:** มีประวัติ 40 วันย้อนหลัง (HN `HIST-…`) · ฐานข้อมูลที่ใส่ข้อมูลตัวอย่างไว้ก่อนหน้านี้ admin กด **สร้างประวัติตัวอย่าง** ได้ (เฉพาะเมื่อยังไม่มีเวลาจริงเลย)

### Staffing Agent: ตารางเวร ทักษะ และความเหนื่อยล้า

แท็บ **บุคลากร** แสดงทุกคน (ผู้จัดตาราง/admin) หรือเฉพาะตัวเอง (ศัลยแพทย์/พยาบาลที่ผูกบัญชีแล้ว): เวรวันนี้ ทักษะ ชั่วโมงผ่าตัดวันนี้ / 7 วัน คะแนนความเหนื่อยล้า และเวลาที่ต้องพักถึง

- **ชั่วโมงทำงานนับจากเคสจริง:** เวลาในห้องผ่าตัดของเคสที่จองไว้ (ใช้เวลาผ่าตัดจริงถ้าบันทึกแล้ว) ย้อนหลัง 7 วันรวมวันนี้ · ยังไม่นับเวรนอกห้องผ่าตัด · คอลัมน์ `staff.current_weekly_hours` ไม่ถูกใช้แล้ว
- **เกณฑ์ (ค่าตั้งต้น ปรับรายคนได้ในตาราง `staff`):** ไม่เกิน `max_hours_per_week` (48) ชม. ใน 7 วัน · ไม่เกิน `max_hours_per_day` (10) ชม./วัน · พัก `min_rest_hours` (8) ชม. หลังเคสที่จบหลัง 22:00 หรือก่อน 06:00 ทั้งก่อนเคสถัดไปในวันเดียวกันและก่อนเคสของวันรุ่งขึ้น
- **เคสปกติ (Elective/Urgent) ห้ามเกินเกณฑ์** · **เคสฉุกเฉินเกินได้** (นโยบาย A): solver เลือกคนที่ยังไม่เกินก่อนเสมอ ถ้าไม่มีจริง ๆ จึงใช้คนที่เกิน แล้วขึ้นกล่องแดงว่าใครเกินเท่าไร บันทึกใน Agent log (`FATIGUE OVERRIDE`) และแสดงในรายละเอียดเคสกับแท็บบุคลากร
- **คะแนนความเหนื่อยล้า** = ค่าที่สูงกว่าระหว่าง (ชม. 7 วัน ÷ เกณฑ์สัปดาห์) กับ (ชม. วันนี้ ÷ เกณฑ์วัน): ต่ำกว่า 70% ปกติ · 70-89% เริ่มล้า · 90-100% ใกล้เกณฑ์ · เกิน 100% เกินเกณฑ์
- **กระจายงาน:** solver เลือกคนที่งานสะสมน้อยกว่า และคิดต้นทุนเพิ่มเมื่อคนเดียวผ่าตัดเกิน 4 ชม./วัน (ทีมที่เข้าขากันยังได้รับความสำคัญก่อน)
- **ทักษะต่อหัตถการ:** `procedures.required_staff_skills` เช่น `{"SCRUB_NURSE": ["ROBOTIC_CERTIFIED"]}` เลือกหัตถการแล้วฟอร์มติ๊กทักษะให้ (แก้ได้) · ถ้าไม่มีใครมีทักษะนั้นระบบบอกชัดเจน · migration 004 ใส่ทักษะพยาบาลหุ่นยนต์ให้หัตถการที่ใช้ห้อง `ROBOTIC_READY`

### ข้อมูลโรงพยาบาล (`/admin`, โหมด Supabase)

ปุ่ม **ข้อมูลโรงพยาบาล** มุมขวาบนของหน้าตาราง (admin แก้ได้ทั้งหมด · ผู้จัดตารางแก้เวร วันลา และปิดห้องได้ ที่เหลือดูอย่างเดียว)

- **เวรและวันลา:** เพิ่มให้หลายคนหลายวันในครั้งเดียว (เลือกวันในสัปดาห์ได้) · เวรปกติ / on-call / ลา (ทั้งวันหรือบางช่วง) · เวลาเลิกน้อยกว่าเวลาเริ่ม = เวรข้ามคืน · ตารางคน × วัน ติ๊กเลือกแล้วลบได้
- **ห้องผ่าตัด:** ประเภท (มาตรฐาน / Hybrid / ความดันลบ) ความสามารถ เวลาทำความสะอาด สถานะ (ใช้งานได้ / ซ่อมบำรุง / ปิดใช้งาน) · **ปิดห้องชั่วคราว** เป็นช่วงเวลา พร้อมเหตุผล (แสดงเป็นแถบแดงในตาราง)
- **บุคลากร:** รหัส ชื่อ บทบาท ความเชี่ยวชาญ ทักษะ เกณฑ์ชั่วโมงรายคน · ปิดใช้งานแทนการลบ
- **เครื่องมือ:** ชนิด (หมวด เวลาอบ CSSD) และเครื่องรายชิ้น (สถานะรายวันยังอัปเดตที่แท็บเครื่องมือของ CSSD)
- ทุกการแก้ไขบันทึกในกิจกรรม และ **ตรวจ 31 วันข้างหน้า** ว่ามีเคสที่จองไว้ขัดกับข้อมูลใหม่หรือไม่ (เช่น คนในทีมลา ห้องถูกปิด) พร้อมปุ่ม **จัดตารางวันนั้นใหม่**

**จัดตารางใหม่ (re-plan):** จัดเคสที่ยังไม่เริ่มของวันนั้นใหม่ โดยเปลี่ยนเวลา/ห้อง/คนให้น้อยที่สุดและแจ้งทีม (ปุ่มอยู่ในแถบเตือนของหน้าตารางด้วย) · เคสที่จัดไม่ได้แล้วในวันนั้นจะไปอยู่ใน **รายการรอผ่าตัด** ใต้ตาราง (เห็นทุกวัน) กด **จองใหม่** เพื่อเลือกวันใหม่โดยใช้คำขอเดิม หรือ **ยกเลิกคำขอ**

### OR Facility Agent: ห้องความดันลบและการปิดห้อง

- ผู้ป่วย **ติดเชื้อทางอากาศ** (วัณโรค หัด อีสุกอีใส โควิด ฯลฯ — ติ๊กในฟอร์ม หรือ Intake Agent จับคำได้เอง) ต้องใช้ห้องประเภท `NEGATIVE_PRESSURE` หรือห้องที่มีความสามารถนี้ และใช้เวลาทำความสะอาดแบบติดเชื้อ · ถ้าไม่มีห้องแบบนี้ ระบบบอกเหตุผลชัดเจน
- ห้องที่ **ปิดชั่วคราว** ใช้ไม่ได้ตลอดช่วงนั้น (รวมเวลาทำความสะอาดหลังเคส) · เคสที่กำลังผ่าตัดอยู่ตอนปิดไม่ถูกย้าย · Agent บอกว่าห้องปิดถึงกี่โมงและเสนอเวลาหลังเปิด
- ห้องสถานะ ซ่อมบำรุง / ปิดใช้งาน ใช้ไม่ได้จนกว่าจะเปลี่ยนสถานะกลับ

### แจ้งเตือนทางมือถือ

ปุ่ม **🔔 แจ้งเตือน** มุมขวาบน (ทุกบทบาท) · ข้อความมีแค่รหัสเคส เวลา และห้อง **ไม่มีชื่อหรือ HN ผู้ป่วย**

- **เรื่องที่แจ้ง** (เลือกเปิด/ปิดได้เอง):
  - เคสของฉันถูกเพิ่ม ย้าย เปลี่ยนเวลาเสร็จ หรือเอาออกจากตาราง (ทุกคนที่บัญชีผูกกับรายชื่อบุคลากร) · คนที่ทำรายการเองไม่ได้รับ
  - เคสฉุกเฉินแทรก: สรุปห้อง/เวลา เคสที่ถูกย้าย รอจัดวันใหม่ และคนที่เกินเกณฑ์ความเหนื่อยล้า (ค่าตั้งต้น: admin, ผู้จัดตาราง)
  - CSSD อบไม่ทันเคสที่จองไว้ (ค่าตั้งต้น: admin, ผู้จัดตาราง, CSSD)
  - เคสยังไม่พร้อมผ่าตัด: มีคนกด "มีปัญหา" ในรายการเช็ก (ทันที) และสรุปเคสของวันถัดไปที่ยังไม่พร้อมวันละครั้ง (ค่าตั้งต้น: admin, ผู้จัดตาราง และศัลยแพทย์เจ้าของเคส · ไม่ส่งหมายเหตุ)
  - เคสในรายการรอเลยหรือใกล้วันที่ควรผ่าตัด (ภายใน 7 วัน): สรุปวันละครั้ง (ค่าตั้งต้น: admin และผู้จัดตาราง ได้ทุกเคส · ศัลยแพทย์ได้เฉพาะเคสของตัวเอง · มีแค่รหัสเคส หัตถการ แพทย์ และจำนวนวัน)
  - ผู้ใช้แจ้งปัญหา/ข้อเสนอแนะ และข้อผิดพลาดใหม่ของระบบ (admin)
- **แจ้งเตือนในเบราว์เซอร์ (ฟรี ไม่ต้องตั้งค่า):** กด "เปิดการแจ้งเตือนบนอุปกรณ์นี้" · Android/คอมพิวเตอร์ใช้ได้ทันที · **iPhone/iPad (iOS 16.4+)** ต้องเปิด Safari → แชร์ → **เพิ่มไปยังหน้าจอโฮม** แล้วเปิดแอปจากไอคอนก่อน · กุญแจ VAPID สร้างเองครั้งแรกและเก็บในฐานข้อมูล
- **LINE:** สร้าง LINE Official Account + Messaging API channel แล้วใส่ `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_CHANNEL_SECRET` (และ `LINE_ADD_FRIEND_URL` ถ้ามี) ใน Render · ตั้ง Webhook URL ใน LINE Developers เป็น `https://<เว็บ>/api/line/webhook` และเปิด "Use webhook" · ผู้ใช้กด "เชื่อม LINE" รับรหัส 6 หลัก แล้วพิมพ์ในแชทของ LINE OA · ข้อความ push นับโควตาของแพ็กเกจ LINE OA (แพ็กเกจฟรีในไทยมีจำนวนจำกัด)
- ส่งในเบื้องหลังหลังบันทึกสำเร็จเท่านั้น ไม่ทำให้การจองช้า · อุปกรณ์ที่เลิกรับถูกลบเอง · ดู "ส่งล่าสุด" และ "ส่งข้อความทดสอบ" ได้ในหน้าต่างแจ้งเตือน

- **จองเลือด** ถามเฉพาะหัตถการที่ติ๊ก "ต้องจองเลือด" (หน้าข้อมูลโรงพยาบาล → หัตถการ หรือคอลัมน์ในไฟล์ Excel) · หัตถการอื่นขึ้น "ไม่ต้องใช้" ให้เอง
- **ในตาราง:** วงกลมมุมขวาของเคส = ตัวเลขรายการที่ยังไม่ได้ · ✓ พร้อม · ! มีปัญหา · กดเคสแล้วเช็กได้ในรายละเอียด · แท็บ **ความพร้อม** แสดงทุกเคสของวันนั้น กดป้ายเพื่อติ๊กเรียบร้อยได้ทันที (กรองเฉพาะที่ยังไม่พร้อมได้)
- **เตือน:** แถบแดงเมื่อมีเคสที่มีปัญหา, แถบเหลืองเมื่อยังไม่พร้อม (เฉพาะเคสที่ยังไม่เริ่ม) และแถบ **เคสของวันถัดไป** (วันแรกที่มีเคสภายใน 3 วัน) ที่ยังไม่พร้อม พร้อมปุ่มไปที่วันนั้น · แจ้งเตือนทางมือถือ: กด "มีปัญหา" แจ้งผู้จัดตารางและศัลยแพทย์ทันที และสรุปเคสวันถัดไปวันละครั้งตั้งแต่ 14:00 (`READINESS_DIGEST_HOUR` เปลี่ยนชั่วโมง หรือ `off` เพื่อปิด · บน Render แผนฟรีที่หลับอยู่จะส่งเมื่อเว็บตื่น)
- ใครเช็กได้: admin, ผู้จัดตาราง, พยาบาล/วิสัญญี (ทุกเคส), ศัลยแพทย์ (เคสของตัวเอง) · CSSD เห็นเฉพาะสถานะ ไม่เห็นหมายเหตุ · **ไม่ห้ามจอง** ใช้เพื่อเตือนเท่านั้น
- ต้องรัน `supabase/migrations/20261108000000_case_readiness.sql` (ก่อนรัน ระบบอื่นใช้ได้ แต่รายการเช็กว่างและแก้ไม่ได้)

### บล็อกห้องผ่าตัดรายสัปดาห์ (หน้าข้อมูลโรงพยาบาล → บล็อกห้อง)

- ตั้งบล็อก: ห้อง · วันในสัปดาห์ (เลือกหลายวันได้) · เวลา · เจ้าของ = **แผนก** (ตรงกับช่อง "ความเชี่ยวชาญ" ของศัลยแพทย์ เช่น Orthopedics) หรือ **ศัลยแพทย์คนเดียว** · เปิดให้คนอื่นกี่วันก่อนผ่าตัด (ค่าตั้งต้น 2) · ช่วงวันที่ใช้ (ไม่บังคับ) · ตารางห้อง × วันแสดงบล็อกทั้งหมด แก้/ลบได้ · ระบบไม่ให้บล็อกทับกัน (admin และผู้จัดตาราง)
- **ตอนจองเคส elective ใหม่:** จองทับบล็อกของคนอื่นไม่ได้ จนกว่าจะเหลือไม่ถึงจำนวนวันที่ตั้งก่อนผ่าตัด หรือเจ้าของ **คืนบล็อกวันนั้น** (ส่วน "คืนบล็อกเฉพาะวัน") · Agent บอกเหตุผล เช่น "บล็อกของ Orthopedics (เปิดให้คนอื่น 2 วันก่อนผ่าตัด)" · เจ้าของบล็อกได้ห้องของตัวเองก่อน · **เคส urgent / ฉุกเฉินใช้ได้เสมอ** · เคสที่จองไว้แล้วไม่ถูกย้ายเพราะบล็อก (รวมตอนแทรกเคสฉุกเฉินหรือจัดตารางใหม่)
- ในตาราง บล็อกเป็นแถบลายจางหลังเคส พร้อมชื่อเจ้าของ (จางลงเมื่อเปิดให้ทุกคนแล้ว)
- **รายงานผู้บริหาร:** การใช้บล็อกต่อเจ้าของ (ชั่วโมงบล็อก, ที่เจ้าของใช้, อัตราใช้, ที่คนอื่นใช้, จำนวนวันที่คืน)
- ต้องรัน `supabase/migrations/20261111000000_or_blocks.sql` · ข้อมูลตัวอย่างมีความเชี่ยวชาญของศัลยแพทย์แล้ว (General Surgery, Orthopedics, Urology, Vascular Surgery)

### สถานะเคสวันนี้ และกระดานสถานะ (`/board`)

- ในรายละเอียดเคส ส่วน **สถานะวันนี้** บันทึกเวลาแต่ละขั้น: มาถึงห้องเตรียมผ่าตัด → **เข้าห้องผ่าตัด** → ลงมีด → เย็บแผลเสร็จ → **ออกจากห้องผ่าตัด** (ไปห้องพักฟื้น) → ออกจากห้องพักฟื้น (กลับหอ/ICU) · กดปุ่ม "บันทึก: … ตอนนี้" ครั้งเดียว หรือใส่เวลาย้อนหลัง · ยกเลิกขั้นล่าสุดได้ · ระบบไม่ให้ขั้นสลับลำดับ และไม่ให้บันทึกเวลาในอนาคต
- **เข้าห้อง–ออกห้อง = เวลาผ่าตัดจริง** ที่รายงานผู้บริหาร (ความแม่นของเวลาที่จอง เวลาทำความสะอาดห้อง เคสแรกตรงเวลา) และการพยากรณ์เวลาใช้ (แทนช่อง "เริ่มจริง/เสร็จจริง" เดิม)
- ใครบันทึกได้: admin, ผู้จัดตาราง, พยาบาล/วิสัญญี (ทุกเคส รวมพยาบาลห้องเตรียมและห้องพักฟื้น), ศัลยแพทย์ (เคสของตัวเอง)
- **กระดานสถานะ** (ปุ่ม 📺 มุมขวาบน · ทุกบทบาทเปิดได้ · อัปเดตเองทุก 30 วินาที · มีปุ่มเต็มจอ): ห้องละการ์ด แสดงเคสที่กำลังใช้ห้องหรือเคสถัดไป สถานะ ตั้งแต่กี่โมง/กี่นาที เคสที่ **ช้ากว่านัด** (เกิน 15 นาทีแล้วยังไม่เข้าห้อง) ความพร้อมที่ยังไม่ครบ และคิวถัดไป · **ไม่มีชื่อหรือ HN ผู้ป่วย**
- **จอสำหรับญาติ** (`/board?family=1`): เฉพาะรหัสเคสและสถานะ (ไม่มีหัตถการหรือชื่อแพทย์) ให้เจ้าหน้าที่แจ้งรหัสเคสกับญาติ · จอต้องเข้าสู่ระบบ ควรสร้างบัญชีบทบาท "staff" หรือ "cssd" แยกไว้สำหรับจอ
- รายงานผู้บริหารมีตาราง **เวลาแต่ละช่วงของเคส** (ห้องเตรียม → เข้าห้อง, เข้าห้อง → ลงมีด, เวลาผ่าตัด, เย็บเสร็จ → ออกห้อง, อยู่ห้องพักฟื้น) เฉลี่ยและมัธยฐาน
- ต้องรัน `supabase/migrations/20261110000000_case_milestones.sql` สำหรับขั้นห้องเตรียม ลงมีด เย็บแผลเสร็จ และออกจากห้องพักฟื้น (ก่อนรัน บันทึกได้เฉพาะเข้าห้อง/ออกห้อง)

### หาวันว่างแรก และรายการรอผ่าตัด (แท็บจองผ่าตัด)

**หาวันว่าง 14 วัน:** กรอกฟอร์มจองตามปกติ ใส่เวลาที่ต้องการ แล้วกดปุ่มนี้แทนการลองทีละวัน

- ระบบตรวจทีละวันตั้งแต่วันที่เลือกด้านบน (ไม่ก่อนวันนี้; วันนี้เริ่มจากเวลาปัจจุบัน) ด้วยการตรวจเดียวกับปุ่ม **ตรวจสอบช่วงเวลา** (Agent ทั้ง 3 + CP-SAT หาเวลาแรกที่ว่างตั้งแต่เวลาที่ขอ รวมบล็อกห้อง) **โดยไม่จองอะไร**
- เสนอ **3 วันแรก** ที่จองได้ พร้อมห้อง เวลา ทีม และเตียง · บอกว่าเวลาที่ขอว่างหรือเลื่อนไปเท่าไร และเตือนถ้าวันนั้นเลย **วันที่ควรผ่าตัด**
- กดปุ่มจองของวันนั้น = ตรวจซ้ำแล้วจองจริง (ถ้ามีคนจองตัดหน้า จะแสดงผลตรวจล่าสุดแทน) แล้วเปิดตารางของวันนั้น
- ข้ามเสาร์-อาทิตย์ได้ (ค่าตั้งต้น) · ดูเหตุผลของวันที่จองไม่ได้ (เช่น แพทย์ไม่มีเวร ห้องปิด) · **ค้นต่อ 14 วัน** ได้ (สูงสุด 28 วันต่อครั้งผ่าน API)
- ค้นแต่ละครั้งใช้เวลาไม่เกิน ~40 วินาที ถ้ายังไม่ครบ ระบบบอกว่าค้นถึงวันไหนและให้กดค้นต่อ

**รายการรอผ่าตัด** (กล่องใต้ตาราง เห็นทุกวัน · ต้องรัน SQL ไฟล์ 015 เพื่อใช้วันที่ควรผ่าตัด):

- มาจาก 2 ทาง: เคสที่ถูกเลื่อนออกจากตาราง (งดผ่าตัดแบบเลื่อน จัดตารางใหม่ เคสฉุกเฉินแทรก) และเคสที่กด **เพิ่มเข้ารายการรอ** จากฟอร์มจอง (ยังไม่มีวันที่เหมาะ หรือผู้ป่วยยังไม่พร้อม)
- **ควรผ่าตัดภายในวันที่** (ไม่บังคับ): ใส่ในฟอร์มจอง หรือเลือกระยะ 2/4/8 สัปดาห์ 3 เดือน · แก้ที่เคสในรายการด้วย **กำหนดวันที่ควรผ่าตัด** · ติดไปกับคำขอเมื่อจองแล้วถูกเลื่อนกลับมา
- **ลำดับ:** ฉุกเฉิน → ด่วน → วันที่ควรผ่าตัดใกล้ที่สุด (ไม่มีกำหนดอยู่ท้าย) → รอนานที่สุด · แสดงจำนวนวันที่รอ
- **เตือน:** "เลยกำหนด N วัน" (ขอบแดง) และ "อีก N วัน" เมื่อเหลือไม่เกิน 7 วัน (ขอบส้ม) พร้อมแถบเตือนบนหน้าตารางสำหรับผู้ที่จองได้
- **แจ้งเตือนมือถือ / LINE วันละครั้ง** (พร้อมสรุปความพร้อมวันถัดไป: `READINESS_DIGEST_HOUR` ค่าตั้งต้น 14:00, `off` = ปิดทั้งสองอย่าง): รายการเคสที่เลยกำหนดและใกล้ครบกำหนด เรียงจากเลยกำหนดนานที่สุด · admin และผู้จัดตารางได้ทุกเคส ศัลยแพทย์ได้เฉพาะเคสของตัวเอง · ส่งทุกวันจนกว่าจะจอง ยกเลิก หรือเลื่อนวันที่ควรผ่าตัด · ไม่ส่งถ้าไม่มีเคสที่ต้องเตือน · หลายเซิร์ฟเวอร์/เริ่มใหม่ไม่ส่งซ้ำ · กดแล้วเปิดรายการรอผ่าตัด
- กันเพิ่มซ้ำ: ผู้ป่วย + ศัลยแพทย์ + หัตถการเดียวกันที่รออยู่แล้ว · เคสฉุกเฉินเข้ารายการรอไม่ได้ (ใช้แท็บฉุกเฉิน) · ศัลยแพทย์จัดการได้เฉพาะเคสของตัวเอง · ทุกการเพิ่ม/แก้บันทึกในกิจกรรม (ไม่มี HN)
- ข้อมูลผู้ป่วยของเคสที่ยังรออยู่ไม่ถูกลบตามระยะเวลา PDPA จนกว่าจะผ่าตัดหรือยกเลิก

### งดผ่าตัดพร้อมเหตุผล

- ในรายละเอียดเคส กด **งดผ่าตัด / ยกเลิกเคสนี้** (admin, ผู้จัดตาราง, ศัลยแพทย์เจ้าของเคส · เคสที่เริ่มแล้วงดไม่ได้) → เลือกเหตุผล ใส่รายละเอียด (ไม่บังคับ ยกเว้น "อื่น ๆ") และเลือก **เลื่อน** (ไปอยู่รายการรอผ่าตัด) หรือ **ยกเลิกคำขอ**
- เหตุผลแบ่งเป็น **ผู้ป่วย** (ไม่พร้อมทางการแพทย์ ไม่ได้งดน้ำงดอาหาร ปฏิเสธ/ขอเลื่อน ไม่มาตามนัด ไม่จำเป็นต้องผ่าตัดแล้ว) และ **โรงพยาบาล** (ห้อง/เวลาไม่พอ ทีมไม่ว่าง เครื่องมือ/วัสดุไม่พร้อม ไม่มีเตียง เลือดไม่พร้อม เอกสารไม่ครบ) · ถ้ารายการเช็กความพร้อมมีปัญหา ระบบเลือกเหตุผลที่ตรงไว้ให้ (เช่น NPO → ไม่ได้งดน้ำงดอาหาร)
- ยกเลิกคำขอในรายการรอผ่าตัดก็ถามเหตุผลเช่นกัน · เคสที่ถูกเลื่อนออกจากวันเพราะ **เคสฉุกเฉินแทรก เคสก่อนหน้าเกินเวลา หรือจัดตารางใหม่** ระบบบันทึกเหตุผลให้เอง
- ทีมในเคสได้รับแจ้ง "งดผ่าตัด" (ไม่บอกเหตุผล) · บันทึกในกิจกรรม
- **รายงานผู้บริหาร:** อัตรางดผ่าตัด (งด ÷ เคสที่นัดในช่วงนั้น) เทียบช่วงก่อน · จำนวนที่งดในวันผ่าตัด · ส่วนที่เป็นเหตุจากโรงพยาบาล (ป้องกันได้) · กราฟแยกเหตุผล · รายการล่าสุด · นับตามวันที่นัด เคสที่เลื่อนหลายครั้งนับทุกครั้ง
- ต้องรัน `supabase/migrations/20261109000000_case_cancellations.sql` (ก่อนรัน งดผ่าตัดได้ แต่ไม่เก็บเหตุผลและรายงานไม่มีส่วนนี้)

### พิมพ์ใบรายการผ่าตัด และ WHO Surgical Safety Checklist (`/print`)

ปุ่ม **🖨 พิมพ์ / WHO checklist** บนหัวตารางผ่าตัด (หรือ **🖨 WHO checklist** ในรายละเอียดเคส) เปิดหน้าพิมพ์ของวันที่แสดง · กด "พิมพ์ / บันทึก PDF" (A4 แนวนอน)

- **ใบรายการผ่าตัด:** ห้องละหน้า · เวลา (และเวลาห้องพร้อม) รหัสเคส ผู้ป่วย หัตถการ (ฉุกเฉิน/ติดเชื้อ/ติดเชื้อทางอากาศ) ทีมแยกตามหน้าที่ เครื่องมือและวัสดุ/รากเทียม เตียงพักฟื้น สถานะความพร้อม และช่องหมายเหตุไว้เขียน
- **WHO Surgical Safety Checklist:** เคสละหน้า · Sign In / Time Out / Sign Out ภาษาไทย (ดัดแปลงจาก WHO 2009) พร้อมข้อมูลเคสใส่ให้แล้ว (ทีม เครื่องมือ รากเทียม เวลาที่คาด เตียงหลังผ่าตัด) · ข้อที่ตรงกับรายการเช็กความพร้อมแสดงสถานะ "ในระบบ" (ใครเช็ก เมื่อไร) · ช่องลงชื่อ และเวลาเข้าห้อง/ลงมีด/เสร็จ/ออกห้อง
- เลือกห้อง (หรือเคสเดียว) ได้ · ติ๊ก **ไม่แสดงชื่อและ HN** สำหรับฉบับติดหน้าห้อง (ซ่อนหมายเหตุความพร้อมด้วย) · บัญชีที่ไม่มีสิทธิ์เห็นผู้ป่วย (CSSD) ได้ฉบับไม่มีชื่ออัตโนมัติ
- ใส่ชื่อโรงพยาบาลบนหัวกระดาษด้วย `HOSPITAL_NAME` ใน Render (ไม่บังคับ)

### รายงานผู้บริหาร (`/reports`)

ปุ่ม **รายงาน** มุมขวาบนของหน้าตาราง (admin และผู้จัดตาราง) · เลือกช่วง 7 / 30 / 90 วัน, เดือนนี้ หรือกำหนดเอง (สูงสุด 1 ปี) · ตัวเลขเทียบกับช่วงก่อนหน้าที่ยาวเท่ากัน

- **อัตราการใช้ห้องผ่าตัด** = เวลาที่ห้องมีเคส (รวมทำความสะอาด) ภายในเวลา elective ÷ เวลา elective ของทุกห้อง (หักช่วงปิดห้อง) · ห้องที่ยังไม่ตั้งเวลา elective คิด 08:00-16:00 · นับเฉพาะวันที่มีผ่าตัด · แยกรายวันและรายห้อง พร้อมชั่วโมงนอกเวลา elective
- **เคสแรกของวันเริ่มตรงเวลา** (ช้าไม่เกิน 15 นาที) และเวลาที่ช้าเฉลี่ย · **เวลาทำความสะอาดห้องจริง** เทียบกับแผน
- **ความแม่นของเวลาที่จอง**: คลาดเฉลี่ยกี่นาที, % ที่ตรง ±15 นาที, % ที่นานเกินจอง, การกระจายของส่วนต่าง และแยกศัลยแพทย์ / หัตถการ (ใช้ปรับเวลามาตรฐานและ preference card)
- **จำนวนเคส** elective / urgent / ฉุกเฉิน ต่อวัน, รอจัดวันใหม่, ยกเลิก, แทรกฉุกเฉิน, จัดตารางใหม่, เกินเกณฑ์ความเหนื่อยล้า
- **ชั่วโมงผ่าตัดของบุคลากร** และ **วัสดุ/รากเทียมที่ใช้**
- **ดาวน์โหลด CSV** ของเคสในช่วงนั้น (เวลาที่จอง เวลาจริง ส่วนต่าง) เปิดใน Excel ได้ · **ไม่มี HN หรือชื่อผู้ป่วย**
- ตัวเลขที่ใช้เวลาจริงคิดจากเคสที่บันทึกเวลาผ่าตัดจริงเท่านั้น หน้ารายงานบอกว่ามีกี่เคส และเตือนเมื่อมีข้อมูลตัวอย่าง (HN `HIST-…`) ปนอยู่
- **เวลาผ่าตัดจริง ก่อนใช้ระบบ เทียบกับช่วงนี้** (ต่อหัตถการ, มัธยฐาน): ก่อนใช้ระบบมาจากประวัติย้อนหลังที่นำเข้า · ช่วงนี้มาจากเคสในระบบ (ไม่รวมข้อมูลตัวอย่าง)
- โหมดข้อมูลจำลองแสดงเฉพาะวันนี้

### Equipment & CSSD Agent: คิว CSSD และนัดซ่อมบำรุง

- **คิว CSSD** (แท็บ **เครื่องมือ** ในหน้าตาราง): ทุกชุดที่ต้องล้าง/อบ แสดงว่ากลับจากเคสไหน กี่โมง ต้องพร้อมกี่โมง เคสถัดไปที่ใช้ และเวลาเผื่อ เรียงจากเร่งที่สุด (แดง = ไม่ทัน, เหลือง = เผื่อน้อยกว่า 30 นาที)
- CSSD **อัปเดตเวลาพร้อมจริง** หรือกด **อบเสร็จแล้ว** ได้จากคิว ถ้าช้ากว่าแผน ระบบบอกเคสที่กระทบทันที พร้อมปุ่มจัดตารางวันนี้ใหม่ (ผู้จัดตาราง)
- **นัดซ่อมบำรุง** (หน้าข้อมูลโรงพยาบาล → เครื่องมือ): ช่วงเวลาที่เครื่องไม่พร้อม เช่น PM ประจำปีของหุ่นยนต์ · Agent ไม่จองเครื่องช่วงนั้น บอกเหตุผล และเสนอเวลาหลังซ่อม · เคสที่จองทับอยู่แล้วถูกแจ้งให้จัดใหม่ (admin, ผู้จัดตาราง, CSSD)

### OR Facility Agent: เวลา elective เตียงพักฟื้น และเวลาพักฟื้น

- **เวลา elective ต่อห้อง** (เช่น 08:00-16:00): เคส elective ต้องเริ่มและเสร็จในช่วงนี้ · เคส urgent / ฉุกเฉินใช้ห้องนอกเวลาได้ · เว้นว่าง = ไม่จำกัด
- **เตียงพักฟื้น** (หน้าข้อมูลโรงพยาบาล → ห้องผ่าตัด): เพิ่มเตียง PACU / ICU, ใส่ว่ามีผู้ป่วยที่ไม่ได้มาจากตารางผ่าตัดถึงเมื่อไร (เช่น ผู้ป่วยอายุรกรรมใน ICU), ปิด/เปิดเตียง และดูว่าเตียงถูกจองหลังผ่าตัดช่วงไหน · Agent บอกว่าเตียงไหนไม่ว่างถึงกี่โมง
- **เวลาพักฟื้นต่อหัตถการ** (แท็บ **หัตถการ**): ระยะเวลาที่ต้องจองเตียงหลังผ่าตัด (ว่าง = PACU 60 นาที / ICU 24 ชม.) ใส่ให้ในฟอร์มจองและแก้รายเคสได้
- แท็บ **หัตถการ**: ชื่อ รหัส ICD-9-CM เวลาผ่าตัดมาตรฐาน ห้องที่ต้องใช้ ICU ความเสี่ยงติดเชื้อ เวลาพักฟื้น และทักษะที่ทีมต้องมี (admin แก้ได้)

### Preference card ของศัลยแพทย์

แท็บ **Preference card** ในหน้าข้อมูลโรงพยาบาล (admin และผู้จัดตารางแก้ได้ทุกท่าน · **ศัลยแพทย์แก้ได้เฉพาะ card ของตัวเอง** ผ่านปุ่ม "Preference card ของฉัน" มุมขวาบนของหน้าตาราง)

- หนึ่ง card ต่อ แพทย์ 1 ท่าน × หัตถการ 1 อย่าง: **เวลาผ่าตัดที่จอง** ± ความคลาดเคลื่อน, **ทีม** (วิสัญญีแพทย์ พยาบาลส่งเครื่องมือ พยาบาลช่วยรอบนอก ศัลยแพทย์ผู้ช่วย · 0 = ไม่ต้องใช้ เช่น ผ่าตัดใช้ยาชาเฉพาะที่), **เครื่องมือที่ใช้ทุกครั้ง** พร้อมจำนวน (เช่น ชุดเครื่องมือ 2 ชุด) และหมายเหตุ (ท่าผู้ป่วย ไหม ขนาดถุงมือ)
- ฟอร์มจองเคสใส่ค่าจาก card ให้ทันทีเมื่อเลือกแพทย์และหัตถการ (แก้รายเคสได้) · Intake Agent ใช้ card เป็นค่าตั้งต้นของการพยากรณ์เวลา
- แต่ละ card แสดง **เวลาจริงจากเคสที่บันทึกไว้** (จำนวนเคส เฉลี่ย ±) · ถ้ามีอย่างน้อย 3 เคสและเฉลี่ยต่างจาก card ตั้งแต่ 15 นาที ขึ้นป้าย "ต่างจากเคสจริง" พร้อมปุ่ม **ใช้ค่าจากเคสจริง** (กรองดูเฉพาะ card เหล่านี้ได้)
- ลบ card แล้ว การจองครั้งถัดไปใช้เวลามาตรฐานของหัตถการและทีมมาตรฐาน · ทุกการแก้ไขบันทึกในกิจกรรม

### Equipment & Inventory Agent: วัสดุสิ้นเปลืองและรากเทียม

แท็บ **วัสดุ/รากเทียม** ในหน้าข้อมูลโรงพยาบาล (admin และ CSSD แก้ได้ · ผู้จัดตารางดูได้)

- **รายการวัสดุ:** รหัส ชื่อ หมวด (รากเทียม / วัสดุสิ้นเปลือง) หน่วย จุดสั่งซื้อ · **รับของเข้า**, **นับสต็อก** (ตั้งยอดตามที่นับได้), **สั่งของ** (จำนวน + วันที่คาดว่าจะมา), รับของที่สั่งไว้ หรือยกเลิกการสั่ง
- **วัสดุที่แต่ละหัตถการใช้** ใส่ให้ในฟอร์มจองอัตโนมัติ แก้จำนวนได้รายเคส (หรือเพิ่มชิ้นอื่น)
- **จองแล้วกันของไว้:** เคสที่จอง "จอง" วัสดุไว้กับคำขอผ่าตัด (ย้ายเวลา/ห้องแล้วยังกันไว้) · เมื่อเคสผ่าตัดเสร็จ (เวลาจริง หรือเวลาที่วางแผนผ่านไปแล้ว) ระบบตัดออกจากสต็อกให้เอง
- **ตรวจตอนจอง:** จองเคสใหม่ไม่ได้ถ้าของไม่พอ โดยนับ ของในคลัง + ของที่สั่งไว้ซึ่งมาถึงภายในวันนั้น − ของที่เคสอื่นจองไว้ (ไม่แย่งของที่เคสวันหลังจองไว้แล้ว) · Agent บอกว่าขาดอะไร เหลือเท่าไร และของจะเข้าเมื่อไร
- **เคสที่จองไว้แล้ว:** ถ้าของไม่พอทีหลัง (นับสต็อกได้น้อยลง ยกเลิกการสั่ง) ระบบให้เคสที่ผ่าตัดก่อนได้ของก่อน แล้วเตือนวันของเคสที่ขาด พร้อมปุ่มจัดตารางใหม่
- **เคสฉุกเฉิน** ใช้ของที่เคสวันหลังจองไว้ได้ (เคสนั้นจะขึ้นเตือนให้สั่งของเพิ่ม) และได้ของก่อนเคส elective วันเดียวกัน (เคสที่ถูกแทนที่ไปอยู่ในรายการรอจัดวันใหม่)
- แถบเตือน **วัสดุใกล้หมด** ในหน้าตาราง เมื่อเหลือให้เคสใหม่ไม่เกินจุดสั่งซื้อ

การทำงานในโหมด Supabase: ทุกคำขออ่านข้อมูลของวันนั้นจากฐานข้อมูลสด · การเขียนทำในทรานแซกชันเดียวภายใต้ advisory lock · ผลจาก engine ต้องผ่าน `validate_schedule` โดยไม่เพิ่มจุดขัดกันใหม่ · exclusion constraint ในฐานข้อมูลเป็นด่านสุดท้าย (ถ้ามีคนเขียนซ้อนจะได้ข้อความให้ลองใหม่ ไม่ใช่จองซ้อน) · ห้อง/เครื่องมือ/เตียงที่ถูกใช้โดยเคสของวันอื่น (เช่นเตียง ICU ข้ามวัน) ถูกนับด้วย

ค่าที่ schema ยังไม่มีและใช้ค่า default: ชั่วโมงทำงานคำนวณจากเคสที่จองในฐานข้อมูล (ไม่อ่าน `current_weekly_hours`)

### สถานะระบบ (`/status`, เฉพาะ admin)

ปุ่ม **⚙ สถานะระบบ** ที่หัวหน้าตารางผ่าตัดและหน้าข้อมูลโรงพยาบาล

- **พร้อมใช้งานจริงหรือยัง**: SQL ครบ, Row Level Security เปิดทุกตาราง, ลบข้อมูลตัวอย่างแล้ว, มีห้อง, มีบุคลากรครบทุกบทบาท, มีเวรใน 7 วันข้างหน้า, ศัลยแพทย์มีความเชี่ยวชาญ, บัญชีแพทย์/พยาบาลผูกกับรายชื่อบุคลากร, มีบัญชีของแต่ละคน · แต่ละข้อมีลิงก์ไปหน้าที่แก้ได้
- **ไฟล์ SQL ในฐานข้อมูล**: ระบบอ่านทุกไฟล์ใน `supabase/migrations` แล้วดูว่าตารางและคอลัมน์ที่ไฟล์สร้างมีในฐานข้อมูลครบหรือยัง (รันแล้ว / รันไม่ครบ / ยังไม่ได้รัน) · ปุ่ม **รัน SQL ที่ยังขาด** รันไฟล์ที่ขาดตามลำดับ ทีละไฟล์ในทรานแซกชันของตัวเอง ถ้าไฟล์ไหนผิดพลาดจะยกเลิกเฉพาะไฟล์นั้นและหยุด · รันได้ทีละคน (advisory lock) · บันทึกผลในกิจกรรม · ไฟล์แรก (โครงสร้างเริ่มต้น) รันซ้ำไม่ได้ จึงรันจากหน้านี้ได้เฉพาะเมื่อฐานข้อมูลยังว่างเปล่า · ฟีเจอร์ใหม่ใช้ได้ทันทีหลังรัน ไม่ต้องรีสตาร์ต
- **การตั้งค่าเซิร์ฟเวอร์**: แต่ละค่าใน Render → Environment ตั้งแล้วหรือยัง (ฐานข้อมูล, บัญชีหลัก, Claude API, LINE, Web Push, `APP_URL`, `HOSPITAL_NAME`, `READINESS_DIGEST_HOUR`, เขตเวลา, solver) · **ไม่แสดงรหัสผ่านหรือคีย์ลับ**
- โหมดสาธิต (ไม่มี `DATABASE_URL`) แสดงเฉพาะการตั้งค่า

### เซิร์ฟเวอร์ งานตั้งเวลา และการสำรองข้อมูล (หน้า ⚙ สถานะระบบ)

- **⬇ ดาวน์โหลดสำรองข้อมูลทั้งหมด (.zip)** (admin): ทุกตารางเป็น CSV อ่านในทรานแซกชันเดียว (ข้อมูลตรงกันทั้งไฟล์) + `manifest.json` + `restore.sql` + `README.txt` วิธีกู้คืนภาษาไทย · ไฟล์มี HN/ชื่อผู้ป่วย จึงถูกบันทึกในบันทึกการเข้าถึงข้อมูลผู้ป่วย (PDPA) ทุกครั้ง
- กู้คืน (ลงฐานข้อมูลใหม่ที่ว่างเปล่า หลังรัน SQL ทุกไฟล์แล้ว) ทำในทรานแซกชันเดียว ปฏิเสธถ้าปลายทางมีข้อมูลอยู่แล้ว:

  ```bash
  DATABASE_URL="<connection string ของฐานข้อมูลใหม่>" python -m app.backup restore orchestra-backup-YYYY-MM-DD.zip
  ```

  หรือแตกไฟล์แล้ว `psql "<connection string>" -f restore.sql` ในโฟลเดอร์นั้น
- สำรองอัตโนมัติจากเครื่องของโรงพยาบาล (เช่น cron ทุกคืน) โดยไม่ต้องเปิดเว็บ (อ่าน connection string จาก environment เท่านั้น ไม่ใส่ในคำสั่ง):

  ```bash
  DATABASE_URL="<connection string>" python -m app.backup dump /secure/backups/orchestra-$(date +%F).zip
  ```

- **สำรองอัตโนมัติทุกคืน (แนะนำ):** ตั้ง 2 ค่าใน Render → Environment แล้วระบบสำรองเองทุกคืน 03:00 (หลังงานลบข้อมูล PDPA 02:00)
  - `SUPABASE_SERVICE_ROLE_KEY`: Supabase → Project Settings → API Keys → คีย์ **service_role** (secret) ใช้อัปโหลดไฟล์เข้า Storage
  - `BACKUP_ENCRYPTION_KEY`: รหัสผ่านที่คุณตั้งเอง อย่างน้อย 16 ตัวอักษร ใช้เข้ารหัสไฟล์ **เก็บไว้อีกที่หนึ่งด้วย** (โปรแกรมจัดการรหัสผ่าน / ซองปิดผนึกที่ฝ่าย IT) ถ้าหาย จะเปิดไฟล์สำรองไม่ได้ · ถ้าเปลี่ยนรหัส ไฟล์เก่ายังต้องใช้รหัสเดิม
  - ไม่บังคับ: `BACKUP_HOUR` (ค่าตั้งต้น 3), `BACKUP_KEEP_DAYS` (14), `BACKUP_BUCKET` (`orchestra-backups`), `SUPABASE_URL` (ปกติหาเองจาก `DATABASE_URL`)
  - ทุกคืน: สร้าง ZIP แบบเดียวกับปุ่มดาวน์โหลด → เข้ารหัส AES-256-GCM (กุญแจจาก scrypt, ทีละ 1 MB ไฟล์ที่ถูกตัด สลับ หรือแก้จะถอดไม่ได้) → อัปโหลดเข้า bucket ส่วนตัว (ระบบสร้างให้ ปฏิเสธถ้าเป็น public) → ตรวจขนาดที่อัปโหลด → ลบไฟล์เก่ากว่า 14 วัน (เก็บ 3 ไฟล์ล่าสุดเสมอ ลบเฉพาะไฟล์ของระบบนี้)
  - ล้มเหลว: ลองใหม่ทุก 15 นาที สูงสุด 3 ครั้งต่อคืน · ขึ้นในรายการข้อผิดพลาดและแจ้ง admin · เช็กลิสต์เป็นสีแดง · บันทึกการเข้าถึงข้อมูลผู้ป่วย (PDPA) บันทึกทุกครั้ง (ผู้ใช้ “system”)
  - หน้า ⚙ สถานะระบบ: สถานะ ไฟล์ที่เก็บไว้ (ดาวน์โหลดไฟล์ `.orcbak` ได้) และปุ่ม **สำรองตอนนี้** สำหรับทดสอบ · Render แผนฟรีที่หลับอยู่ตอน 03:00 จะสำรองเมื่อเว็บตื่น
  - กู้คืนจากไฟล์ที่เข้ารหัส (ตั้ง `BACKUP_ENCRYPTION_KEY` หรือพิมพ์เมื่อถาม):

    ```bash
    DATABASE_URL="<connection string ของฐานข้อมูลใหม่>" python -m app.backup restore orchestra-YYYY-MM-DD-0300.orcbak
    ```

    หรือ `python -m app.backup decrypt ไฟล์.orcbak ไฟล์.zip` เพื่อได้ไฟล์ zip แบบเดิม
  - Supabase แผนฟรีรับไฟล์ละไม่เกิน 50 MB (ไฟล์สำรองปกติเล็กกว่านั้นมาก) · ไฟล์อยู่ในโปรเจกต์ Supabase เดียวกับฐานข้อมูล: กันข้อมูลหายจากการลบหรือแก้ผิด แต่ถ้าบัญชี Supabase หายทั้งบัญชี ไฟล์ก็หายด้วย จึงยังควรดาวน์โหลดเก็บเองเป็นครั้งคราว
- หน้าสถานะแสดง: เซิร์ฟเวอร์เริ่มทำงานเมื่อไร และเริ่มใหม่กี่ครั้งใน 24 ชม. (บ่อย = แผนฟรีที่หลับเมื่อไม่มีคนใช้) · งานสรุปความพร้อม (ตามเวลาที่ตั้ง) และงานลบข้อมูล PDPA (02:00) ทำงานล่าสุดเมื่อไร · สำรองข้อมูลล่าสุด · เช็กลิสต์เตือนเมื่อไม่ได้สำรองเกิน 7 วัน หรืองานตั้งเวลาไม่ได้ทำงาน

#### แผนของ Render และ Supabase สำหรับใช้งานจริง

- **Render แผนฟรี** หลับเมื่อไม่มีคำขอเข้ามา 15 นาที ([Render changelog](https://render.com/changelog/free-web-services-now-remain-active-while-receiving-websocket-messages)) คนแรกที่เปิดต้องรอให้เซิร์ฟเวอร์ตื่น และงานตั้งเวลา (สรุปความพร้อม, ลบข้อมูลตาม PDPA, แจ้งเตือน) ไม่ทำงานระหว่างหลับ (ทำเมื่อมีคนเปิดเว็บครั้งถัดไป) → ใช้งานจริงควรใช้ instance แบบเสียเงิน (ไม่หลับ) · ทางเลือกชั่วคราว: ให้บริการตรวจ uptime เรียก `/api/health` ทุก 5–10 นาที
- **Supabase แผนฟรี** ไม่มีการสำรองข้อมูลอัตโนมัติ และหยุดโปรเจกต์เมื่อไม่มีการใช้งาน 1 สัปดาห์ ([Supabase pricing](https://supabase.com/pricing)) → ใช้งานจริงกับข้อมูลผู้ป่วยควรใช้แผนที่มี daily backups และยังควรดาวน์โหลดไฟล์สำรองเก็บไว้เองเป็นประจำ (แผนฟรี: อย่างน้อยสัปดาห์ละครั้ง)
- ราคาและเงื่อนไขของทั้งสองบริการเปลี่ยนได้ ตรวจที่หน้าราคาของผู้ให้บริการก่อนตัดสินใจ

### เชื่อมต่อระบบ HIS ของโรงพยาบาล (หน้าข้อมูลโรงพยาบาล → เชื่อมต่อ HIS, เฉพาะ admin · ต้องรัน SQL ไฟล์ 017)

HIS ของโรงพยาบาลมักอยู่ในเครือข่ายภายใน เซิร์ฟเวอร์บน Render เรียกเข้าไปไม่ได้ จึงออกแบบให้ **HIS เป็นฝ่ายเรียกเข้ามา** (HTTPS ขาออกจากโรงพยาบาล) ด้วย API key · ปิดอยู่จนกว่าจะสร้าง key

| เรียก | สิทธิ์ (scope) | ทำอะไร |
|---|---|---|
| `GET /api/his/v1/ping` | อย่างใดก็ได้ | ทดสอบ key |
| `POST /api/his/v1/surgery-requests` | `requests:write` | สร้าง / แก้ไข / ยกเลิก (`"action": "cancel"`) ใบขอผ่าตัด อ้างด้วย `his_ref` (ส่งซ้ำได้ ไม่เกิดรายการซ้ำ) |
| `POST /api/his/v1/surgery-requests/batch` | `requests:write` | ครั้งละไม่เกิน 200 รายการ |
| `GET /api/his/v1/surgery-requests/{his_ref}` | `schedule:read` | สถานะ: waiting / booked (วัน เวลา ห้อง) / in_progress / done / cancelled |
| `GET /api/his/v1/schedule?date=YYYY-MM-DD` | `schedule:read` | ตารางผ่าตัดของวัน (มี HN และ `his_ref`) |

- **Key:** header `Authorization: Bearer <key>` (หรือ `X-API-Key`) · เก็บเฉพาะ hash (SHA-256) แสดง key ครั้งเดียวตอนสร้าง · แยก key ต่อระบบ เลือกสิทธิ์ได้ · ยกเลิกได้ทันที · ไม่ต้องใช้ session (ไม่ redirect ไปหน้า login)
- **ขีดจำกัด:** ตรวจ key ก่อนอ่านข้อมูลที่ส่งมา · ข้อมูลต่อครั้งไม่เกิน 1 MB · ไม่เกิน 300 ครั้ง/นาที และ 1,200 ใบขอ/นาที ต่อ key (batch นับทุกใบ) · ส่ง key ผิดเกิน 30 ครั้ง/นาทีจาก IP เดียวกัน รอ 1 นาที (429) · ใน batch ใบที่ผิดตอบเป็นรายใบ ใบอื่นยังทำต่อ · แจ้งเตือนจาก HIS ไม่เกิน 20 เรื่อง (ฉุกเฉิน 60) ต่อ 10 นาที เกินนั้นแจ้งครั้งเดียวว่าหยุดแจ้งชั่วคราว
- **ช่องข้อมูลใบขอ:** `his_ref`, `hn`, `patient_name`, `surgeon_code` (+`surgeon_name`), `procedure_code` (ICD-9-CM หรือรหัสของ HIS) และ/หรือ `procedure_name`, `urgency`, `duration_mins` (ไม่ส่ง = preference card / เวลามาตรฐาน), `requested_date`, `due_date`, `requires_icu`, `airborne` · รายละเอียดทุกช่องที่ `/api/docs` (หัวข้อ HIS)
- **จับคู่รหัส:** ตารางจับคู่ก่อน → รหัสพนักงานของศัลยแพทย์ → ICD-9-CM / ชื่อหัตถการ · ไม่รู้จัก = ข้อความรอใน **รหัสที่ยังจับคู่ไม่ได้** (ระบบเดาจากชื่อให้แต่ไม่ใช้เอง) จับคู่แล้วประมวลผลใหม่ให้อัตโนมัติ · แจ้ง admin ครั้งแรกที่เจอรหัสใหม่
- **ผลแต่ละข้อความ:** บันทึกแล้ว / ไม่มีอะไรเปลี่ยน (ไม่เก็บ) / รอจับคู่รหัส / ต้องดำเนินการ / ข้อมูลไม่ถูกต้อง · ดูย้อนหลังได้ในแท็บ
- **ความปลอดภัยของตาราง:** คำขอที่ยังรอ: แก้และยกเลิกตาม HIS ได้เลย · **เคสที่จองแล้ว: ไม่ย้ายหรือยกเลิกเอง** (แก้ได้เฉพาะวันที่) ถ้า HIS เปลี่ยนแพทย์/หัตถการ/ยกเลิก จะเป็น "ต้องดำเนินการ" และแจ้งผู้จัดตาราง · คำขอฉุกเฉินจาก HIS ขึ้นบนสุดของรายการรอและแจ้งทันที (หัวข้อแจ้งเตือน "ข้อความจากระบบ HIS")
- **ข้อความเก่าไม่ทับข้อความใหม่:** เมื่อ HIS ส่งใบเดิมมาใหม่ (แก้หรือยกเลิก) ข้อความเก่าของเลขที่นั้นที่ยังรอจับคู่รหัสจะไม่ถูกใช้อีก · ยกเลิกใบที่ยังรอจับคู่รหัส = ยกเลิกได้เลย
- **PDPA:** รับเฉพาะที่จำเป็นต่อการนัด (ไม่รับผลแล็บหรือประวัติการรักษา) · ข้อความในกล่องรับข้อมูลลบ HN/ชื่อทันทีเมื่อบันทึกแล้ว หรือเมื่อครบ 30 วัน (แถวเก็บ 180 วัน · ล้างทุกคืนพร้อมงาน PDPA แม้ HIS หยุดส่ง) · การที่ HIS อ่านตาราง/สถานะถูกบันทึกในบันทึกการเข้าถึงข้อมูลผู้ป่วย · กิจกรรมไม่มี HN หรือเลขที่ใบขอ · ชื่อหัตถการจาก HIS ผ่านการปิด HN/ชื่อ · เคสที่ลบข้อมูลระบุตัวตนแล้ว เลขที่ใบขอเหลือเป็นค่า hash ทางเดียว: HIS ส่งใบเดิมซ้ำจะไม่สร้างเคสใหม่และไม่ใส่ชื่อกลับ
- **ทดลองก่อนเชื่อมจริง:** หัวข้อ "ทดลองส่งใบขอผ่าตัด" ในแท็บ ใช้ขั้นตอนเดียวกับ API จริง
- **ต่อยอด:** ถ้าภายหลังเรียก API ของโรงพยาบาลได้ (เช่น ค้นชื่อผู้ป่วยจาก HN) ให้เขียนตัวเชื่อมที่ส่งข้อมูลเข้า `His.receive()` ขั้นตอนเดียวกัน ไม่ต้องแก้ส่วนอื่น

### แจ้งปัญหา / ข้อเสนอแนะ และข้อผิดพลาดของระบบ (ช่วงทดลองใช้)

**ผู้ใช้ทุกบทบาท:** ปุ่ม **💬 แจ้งปัญหา / ข้อเสนอแนะ** มุมขวาล่างของหน้าตาราง ข้อมูลโรงพยาบาล รายงาน สถานะระบบ PDPA และคู่มือ (`/feedback.js` ตัวเดียวใช้ร่วมกัน · ไม่แสดงบนหน้าพิมพ์และกระดานสถานะ)

- เลือก ปัญหา / ข้อเสนอแนะ / สอบถาม แล้วเขียนรายละเอียด · ระบบแนบ **หน้าที่ใช้** (path วันที่ และแท็บเท่านั้น) **เวลา** ชื่อและบทบาทผู้แจ้ง และชนิดเบราว์เซอร์ · ไม่แนบข้อมูลผู้ป่วย
- ข้อความถูก **ปิด HN เลขบัตร เบอร์โทร และชื่อหลังคำนำหน้า** ก่อนเก็บ (ตัวเดียวกับที่ใช้ก่อนส่งให้ Claude) และหน้าต่างเตือนไม่ให้พิมพ์ข้อมูลผู้ป่วย
- ผู้แจ้งเห็นสถานะและบันทึกจากผู้ดูแลได้ที่ **เรื่องที่คุณแจ้งล่าสุด** · ส่งได้ไม่เกิน 20 เรื่องต่อชั่วโมงต่อคน

**ข้อผิดพลาดที่ระบบเก็บเอง:** ข้อผิดพลาดที่ไม่คาดคิดของ API (ผู้ใช้เห็นข้อความภาษาไทยแทน 500), งานเบื้องหลังที่บันทึก error (แจ้งเตือน สรุปความพร้อม ลบข้อมูลตาม PDPA การเชื่อมฐานข้อมูล) และ error ของหน้าเว็บในเบราว์เซอร์ (ไม่เกิน 5 ครั้งต่อหน้า 30 ครั้งต่อชั่วโมงต่อคน)

- ข้อผิดพลาดเดียวกัน (ที่เดียวกัน ข้อความเดียวกัน ไม่นับตัวเลข) รวมเป็นแถวเดียวพร้อมจำนวนครั้ง · ข้อความถูกปิดข้อมูลผู้ป่วยแบบเดียวกัน
- ถ้าฐานข้อมูลล่ม ระบบเก็บไว้ในหน่วยความจำและไม่ลองเขียนซ้ำ 1 นาที (ไม่ทำให้หน้าเว็บช้าลง)

**ผู้ดูแลระบบ:** หน้า **⚙ สถานะระบบ** หัวข้อ **เรื่องที่ผู้ใช้แจ้ง** (รับทราบ / แก้แล้ว / เปิดเรื่องใหม่ พร้อมบันทึกถึงผู้แจ้ง) และ **ข้อผิดพลาดของระบบ** (แก้แล้ว ถ้าเกิดอีกจะกลับมาพร้อมป้าย "เกิดอีกหลังแก้แล้ว") · รายการ "พร้อมใช้งานจริงหรือยัง" แสดงจำนวนเรื่องใหม่ · แจ้งเตือนมือถือ/LINE หัวข้อใหม่ "ผู้ใช้แจ้งปัญหาหรือข้อเสนอแนะ และข้อผิดพลาดใหม่ของระบบ" (เปิดตั้งต้นสำหรับ admin · ข้อผิดพลาดแจ้งไม่เกิน 1 ครั้งต่อ 15 นาที · **ไม่มีข้อความที่ผู้ใช้พิมพ์ในแจ้งเตือน**)

หน้าตั้งค่าแจ้งเตือนแสดงเฉพาะหัวข้อที่บทบาทนั้นได้รับจริง

### คู่มือการใช้งาน (`/help`)

ปุ่ม **❓ วิธีใช้** ที่หัวหน้าตารางผ่าตัด ข้อมูลโรงพยาบาล และสถานะระบบ · ลิงก์ “วิธีใช้งาน / ลืมรหัสผ่าน” ในหน้าเข้าสู่ระบบ (เปิดได้โดยไม่ต้องเข้าสู่ระบบ)

- แยกเป็น **เริ่มต้นใช้งาน (ทุกคน)**, **ผู้จัดตาราง**, **ศัลยแพทย์**, **วิสัญญี / พยาบาล**, **CSSD**, **ผู้ดูแลระบบ** และ **คำถามที่พบบ่อย** · เปิดมาตรงคู่มือของบทบาทผู้ใช้เอง
- **🖨 พิมพ์คู่มือนี้** = เริ่มต้นใช้งาน + บทบาทที่เลือก + คำถามที่พบบ่อย (เอกสารแจกตอนอบรม A4) · **พิมพ์ทุกบทบาท** = ทั้งเล่ม
- ลิงก์ตรงไปยังบทบาทได้ เช่น `/help#staff`, `/help#cssd`
- `tests/test_help.py` ตรวจว่าชื่อปุ่ม/เมนูทุกชื่อในคู่มือ (ที่ครอบด้วย `<kbd>`) ยังมีอยู่จริงในหน้าเว็บ ถ้าเปลี่ยนชื่อปุ่มต้องแก้คู่มือด้วย

### ข้อมูลผู้ป่วยและ PDPA (`/privacy`, เฉพาะ admin · ต้องรัน SQL ไฟล์ 013)

ปุ่ม **🔒 PDPA** ในหน้า ⚙ สถานะระบบ

- **ใครเห็นข้อมูลผู้ป่วยเมื่อไร:** บันทึกทุกครั้งที่มีคนเห็น HN / ชื่อผู้ป่วย (เปิดตารางผ่าตัด, พิมพ์ใบรายการ/WHO checklist, ค้นหาด้วย HN) ลงตาราง `patient_access_log`: เวลา ผู้ใช้ บทบาท สิ่งที่ทำ วันที่ของตาราง จำนวนผู้ป่วย เลขเคส และ IP · เก็บเลขเคส ไม่เก็บ HN หรือชื่อ · เปิดวันเดิมซ้ำภายใน 30 นาทีโดยไม่มีเคสใหม่ไม่บันทึกซ้ำ · บทบาทที่ไม่เห็นข้อมูลผู้ป่วย (CSSD) ไม่ถูกบันทึก
- ค้นได้ตามผู้ใช้ ช่วงวันที่ เลขเคส หรือ **HN** ("ใครเคยเห็นผู้ป่วยคนนี้") · การค้นด้วย HN ถูกบันทึกด้วย
- **ระยะเวลาเก็บข้อมูลระบุตัวผู้ป่วย:** ตั้งจำนวนวันหลังผ่าตัด (อย่างน้อย 30 วัน) · ทุกคืน 02:00 ระบบลบ HN (เป็น `ANON-…`) ชื่อ ข้อความคำขอ หมายเหตุเช็กลิสต์และการงดผ่าตัด และ HN ในบันทึกกิจกรรม ของเคสที่เสร็จหรือถูกยกเลิกเกินกำหนด · เวลา ห้อง หัตถการ ทีมยังอยู่ (รายงานและการพยากรณ์เวลายังใช้ได้) · เคสที่รอจัดวันไม่ถูกลบ · กด "ลบตอนนี้" ได้ · บันทึกการเข้าถึงเก็บ 730 วัน (ตั้งได้)
- **งานเดียวกันทุกคืน (ระยะเวลาคงที่):** ล้าง HN/ชื่อในกล่องรับข้อมูล HIS ที่เกิน 30 วัน · เลขที่ใบขอ HIS ของเคสที่ลบข้อมูลแล้วเหลือเป็น hash · ลบเรื่องที่ผู้ใช้แจ้งที่เกิน 365 วัน (ที่แก้แล้วเกิน 180 วัน) และข้อผิดพลาดที่ไม่เกิดซ้ำเกิน 180 วัน · รายการข้อผิดพลาดเก็บไม่เกิน 1,000 แบบ

ความปลอดภัยของข้อมูลผู้ป่วยตามบทบาท:
- CSSD ไม่เห็น HN ชื่อ หมายเหตุที่พิมพ์เอง (เหตุผลงดผ่าตัด หมายเหตุเตียง เช็กลิสต์) หรือข้อความแจ้งเปลี่ยนแปลงที่มี HN
- บันทึกเวลาเข้า/ออกห้องผ่าตัด (เวลาจริง) ได้เฉพาะทีมของเคส · ขั้นอื่น (รับเข้าห้องเตรียม ห้องพักฟื้น) พยาบาลที่ไม่ได้อยู่ในทีมบันทึกได้
- ข้อความที่ส่งให้ Claude อ่าน: ซ่อน HN (รวม H.N., `54321/66`, เลขที่ผู้ป่วย), เลขบัตรประชาชน, เบอร์โทร และชื่อหลังคำนำหน้า (นาย/นาง/นางสาว/ด.ช./ด.ญ./Mr/Mrs) ก่อนส่ง · การพูดด้วยเสียงส่งเสียงไปแปลงที่ Google/Apple จึงไม่ควรพูดชื่อหรือ HN
- การแจ้งเตือน LINE / มือถือ มีแค่เลขเคส เวลา ห้อง ไม่มี HN หรือชื่อ · ที่อยู่รับแจ้งเตือนต้องเป็นบริการ push ของเบราว์เซอร์ (Chrome/Edge/Firefox/Safari) ไม่เกิน 10 อุปกรณ์ต่อคน · รหัสเชื่อม LINE ผิดได้ 5 ครั้งต่อ 15 นาที
- ไฟล์ CSV / Excel ที่ดาวน์โหลด: ข้อความที่ขึ้นต้นด้วย `=`, `+`, `-`, `@` ถูกเก็บเป็นข้อความ (ไม่กลายเป็นสูตรใน Excel) · ไฟล์ที่อัปโหลดอ่านไม่เกิน 20 แผ่น 60 คอลัมน์

### เริ่มใช้งานจริง: นำเข้าข้อมูลจาก Excel (หน้าข้อมูลโรงพยาบาล → นำเข้า/ส่งออก Excel, เฉพาะ admin)

1. **ดาวน์โหลดไฟล์:** "ข้อมูลปัจจุบัน" (แก้แล้วอัปโหลดกลับ = แก้ทีละมาก ๆ) หรือ "แบบฟอร์มเปล่า" · ไฟล์เดียวมีแผ่น ห้องผ่าตัด เตียงพักฟื้น ชนิดเครื่องมือ เครื่องมือรายชิ้น บุคลากร วัสดุและรากเทียม หัตถการ และ Preference card + แผ่น **วิธีกรอก** ที่อธิบายทุกคอลัมน์
2. **กรอกใน Excel:** ช่องตัวเลือกมีรายการให้เลือก (พิมพ์ภาษาไทยได้ เช่น ศัลยแพทย์ ซ่อมบำรุง ใช่/ไม่) · รายการคั่นด้วย `,` · เครื่องมือ/วัสดุพร้อมจำนวนคั่นด้วย `;` เช่น `LAPAROSCOPY_TRAY x2; C_ARM` · คอลัมน์รหัสและเวลาตั้งเป็นข้อความไว้แล้ว (06.4 หรือ 08:00 ไม่ถูกแปลงเป็นตัวเลข)
3. **อัปโหลด → ตรวจ:** ระบบตรวจทุกแถวด้วยกฎเดียวกับหน้าจอ แล้วแสดงต่อแผ่นว่าเพิ่ม/แก้ไข/ไม่เปลี่ยน/ผิดกี่แถว พร้อมเลขแถวใน Excel และค่าที่จะเปลี่ยน (เดิม → ใหม่) · **ยังไม่บันทึกอะไร**
4. **ยืนยันนำเข้า:** ได้เฉพาะไฟล์ที่ไม่มีแถวผิดเลย และบันทึกทั้งไฟล์ในทรานแซกชันเดียว (สำเร็จทั้งหมดหรือไม่บันทึกเลย) · บันทึกในกิจกรรมหนึ่งรายการ · ถ้าเคสที่จองไว้ขัดกับข้อมูลใหม่ มีปุ่มจัดตารางวันนั้นใหม่

กติกาการจับคู่: ห้อง/เตียง/บุคลากร/วัสดุ ด้วยรหัส · เครื่องมือรายชิ้นด้วยหมายเลขเครื่อง · ชนิดเครื่องมือด้วยชื่อ · หัตถการด้วยรหัส ICD-9-CM หรือชื่อ · preference card ด้วยรหัสศัลยแพทย์ + หัตถการ (ไม่สนตัวพิมพ์เล็ก/ใหญ่) · **รายการที่ไม่มีในไฟล์ไม่ถูกลบ** (ปิดใช้งานด้วยคอลัมน์ "ใช้งาน") · คอลัมน์ที่ลบออกจากไฟล์ = คงค่าเดิม · ช่องว่าง: ข้อความ/รายการ/เวลา = ล้างค่า, ตัวเลข/ตัวเลือก = คงค่าเดิม · สต็อกวัสดุ: ไฟล์แสดงยอดในระบบแบบดูอย่างเดียว และเปลี่ยนยอดเฉพาะเมื่อกรอกช่อง "นับได้จริง" (ไฟล์เก่าจึงไม่ทับยอดที่เปลี่ยนไปแล้ว) · รับ .xlsx (หรือ CSV ทีละแผ่น รวม CSV จาก Excel ภาษาไทย) ไม่เกิน 5 MB · ตารางเวรใช้ไฟล์แยก (หัวข้อถัดไป)

### ประวัติผ่าตัดย้อนหลังจาก Excel (หน้าข้อมูลโรงพยาบาล → นำเข้า/ส่งออก Excel, เฉพาะ admin · ต้องรัน SQL ไฟล์ 014)

ให้ระบบประเมินเวลาผ่าตัดได้แม่นตั้งแต่วันแรก แทนที่จะรอเก็บเวลาจริงหลายสัปดาห์

1. **ดาวน์โหลดแบบฟอร์มประวัติผ่าตัด (.xlsx):** แผ่น **วิธีกรอก** + แผ่น **ประวัติผ่าตัด** ที่มีรายการศัลยแพทย์/หัตถการ/ความเร่งด่วนให้เลือก (ใส่บุคลากรและหัตถการให้ครบก่อน)
2. **กรอก 1 แถว = 1 เคส:** วันที่ (พ.ศ./ค.ศ., วันที่ของ Excel ก็ได้), ศัลยแพทย์ (รหัสหรือชื่อ ไม่สน นพ./พญ./Dr.), หัตถการ (ชื่อหรือรหัส ICD-9), เวลาเข้าห้อง/ออกห้อง (ข้ามเที่ยงคืนได้) **หรือ** ระยะเวลาจริง (นาที) · ไม่บังคับ: เวลาที่จอง ห้อง ความเร่งด่วน · ใช้ไฟล์ที่ export จาก HIS ได้ ถ้าหัวคอลัมน์ใกล้เคียง (เช่น Date / Surgeon / Operation / In / Out / Duration) และรับ CSV
3. **ตรวจไฟล์ประวัติ:** ไม่บันทึกอะไร แสดงแถวที่ผิด (ไม่พบแพทย์/หัตถการ วันที่ในอนาคต ไม่มีเวลา) พร้อมเลขแถว, แถวที่ข้าม (เก่ากว่า 2 ปี, เวลาต่างจากเวลามาตรฐานของหัตถการเกิน ¼–4 เท่า ซึ่งน่าจะพิมพ์ผิด, ซ้ำในไฟล์, เคยนำเข้าแล้ว) และเวลามัธยฐานของแต่ละคู่แพทย์-หัตถการ
4. **นำเข้าเคสที่ถูกต้อง:** แถวที่ผิดไม่ถูกนำเข้า (แก้แล้วอัปโหลดซ้ำได้ เคสเดิมไม่ซ้ำ) · บันทึกในกิจกรรม · แต่ละไฟล์เป็น "ชุด" ที่ลบทั้งชุดได้ถ้านำเข้าผิดไฟล์

- **ไม่เก็บข้อมูลผู้ป่วย:** คอลัมน์ HN/ชื่อผู้ป่วยในไฟล์ถูกข้าม (มีคำเตือน) · ตาราง `case_history` ไม่มีคอลัมน์ผู้ป่วย จึงไม่อยู่ในขอบเขตการลบตามระยะเวลา PDPA
- **ใช้ที่ไหน:** การพยากรณ์เวลาผ่าตัด (Intake Agent) และประวัติใน preference card นับเคส 2 ปีล่าสุด · รายงานผู้บริหารมีตารางเทียบเวลาผ่าตัดจริงก่อน/หลังใช้ระบบ
- ไม่เข้าตารางผ่าตัด ไม่จองห้อง และไม่นับในอัตราการใช้ห้อง (เป็นข้อมูลอ้างอิงเท่านั้น)

### ตารางเวรทั้งเดือนจาก Excel (แท็บเวรและวันลา, admin และผู้จัดตาราง)

- **ดาวน์โหลดตารางเวร:** เลือกเดือน (และบทบาท) ได้ไฟล์ คน × วัน ช่องหนึ่งคือเวรของวันนั้นเป็น **รหัสเวร** · แผ่น **รหัสเวร** กำหนดว่ารหัสไหนคือเวรอะไรกี่โมง แก้เป็นรหัสของโรงพยาบาลเองได้ (ระบบจำรหัสจากไฟล์ล่าสุดที่นำเข้า) · รหัสตั้งต้น:

  | รหัส | ความหมาย |
  |---|---|
  | `ช` / `บ` / `ด` | เวรเช้า 08:00-16:00 / บ่าย 16:00-24:00 / ดึก 00:00-08:00 |
  | `OC` | on-call 16:00 ถึง 08:00 ของวันถัดไป |
  | `ล` `ลป` `ลพ` `ปช` | ลา / ลาป่วย / ลาพักร้อน / ประชุม-อบรม (ทั้งวัน) |
  | `-` `หยุด` `OFF` | วันหยุด ไม่มีเวร |

- **ในช่อง:** หลายเวรคั่นด้วย `/` เช่น `ช/บ` · ใส่เวลาเองได้ เช่น `07:30-15:30` หรือ `ล 08:00-12:00` (ลาครึ่งวัน) · เวลาเลิกน้อยกว่าเวลาเริ่ม = ข้ามคืน
- **หัวคอลัมน์:** วันที่จริง, `1/11/2569` (พ.ศ. ได้), หรือเลข 1-31 ถ้าชื่อแผ่น/หัวตาราง/เดือนที่เลือกบอกเดือน (ตารางที่ข้ามเดือน เช่น 16-31 แล้ว 1-15 ก็ได้) · แถวจับคู่ด้วยรหัสพนักงาน หรือชื่อถ้าไม่มีรหัส · รับ CSV ด้วย
- **ความหมายของไฟล์:** ทุกคนและทุกวันที่มีในไฟล์ = ตารางเวรของวันนั้นทั้งหมด (**ช่องว่าง = ไม่มีเวร**) · คนหรือวันที่ไม่มีในไฟล์ไม่ถูกแตะ · ช่องที่ไม่ได้แก้ไม่ถูกเขียนใหม่ (วันลาที่มีหมายเหตุเองยังอยู่)
- **ตรวจก่อนบันทึก:** แสดงจำนวนวันที่เปลี่ยน เวรใหม่ เวรเดิมที่ถูกแทน และรายคน (เดิม → ใหม่) · ช่องที่ผิดบอกตำแหน่งช่อง เช่น `H17` · นำเข้าได้เมื่อไม่มีช่องผิด บันทึกในทรานแซกชันเดียว บันทึกกิจกรรมหนึ่งรายการ และบอกวันที่มีเคสจองไว้ขัดกับเวรใหม่ (เช่น ศัลยแพทย์ลาวันที่มีเคส) พร้อมปุ่มจัดตารางใหม่
- แก้ได้ตั้งแต่ 62 วันย้อนหลังถึง 400 วันข้างหน้า · ไฟล์ละไม่เกิน 93 วัน

**ลบข้อมูลตัวอย่าง** (ส่วนที่ 3 ของแท็บนำเข้า/ส่งออก Excel):
- **ลบเคสตัวอย่างและประวัติตัวอย่าง:** เคสตัวอย่างของวันแรก และประวัติเวลาผ่าตัด 40 วัน (HN `HIST-…`) · ห้อง บุคลากร และข้อมูลอื่นยังอยู่ · หลังลบ รายงานผู้บริหารและ Intake Agent ใช้เฉพาะเคสจริง
- **ล้างข้อมูลโรงพยาบาลทั้งหมด:** ลบห้อง เตียง บุคลากร เวร เครื่องมือ หัตถการ preference card วัสดุ และเคสทั้งหมด (พิมพ์ "ล้างข้อมูล" เพื่อยืนยัน) · **บัญชีผู้ใช้และการตั้งค่าแจ้งเตือนยังอยู่** แต่ต้องผูกบัญชีกับรายชื่อบุคลากรใหม่หลังนำเข้า · กิจกรรมเดิมยังเก็บไว้เป็นประวัติ
- ลำดับที่แนะนำ: ดาวน์โหลดข้อมูลปัจจุบันเก็บไว้ → แก้เป็นข้อมูลจริง (หรือใช้แบบฟอร์มเปล่า) → ล้างข้อมูล → อัปโหลดไฟล์ → ผูกบัญชีผู้ใช้ → นำเข้าตารางเวรจาก Excel ที่แท็บเวรและวันลา

## การใช้งาน

```python
from orchestra_engine import ORchestraOptimizer, OperatingRoom, EquipmentUnit, StaffMember, SurgeryCase, hm

optimizer = ORchestraOptimizer(rooms, equipments, staff, beds, team_synergy=synergy)
day = optimizer.solve_schedule(cases, "Scenario Name")

# เคสฉุกเฉินแทรก: เคสที่เริ่มไปแล้วถูกล็อก เคสอื่นขยับให้น้อยที่สุด
after = optimizer.insert_emergency(day, cases, [emergency_case], now_min=hm("10:30"))
# ผ่าตัดยืดเยื้อ
after = optimizer.handle_overrun(day, cases, "C04", new_duration_mins=270, now_min=hm("11:00"))
after.changes        # เคสที่เปลี่ยน (เวลา/ห้อง/ทีม/เครื่องมือ/เตียง)
after.notifications  # ข้อความแจ้งเตือนรายบุคคล

# ขอเวลาเจาะจง: Agent 3 ตัวสแกนพร้อมกัน ถ้าผ่านหมดล็อกเลย ถ้าไม่ผ่าน CP-SAT หาช่วงถัดไปที่พร้อมครบ
check = optimizer.check_slot(day, new_case, hm("09:00"))   # เคสที่จองไว้แล้วไม่ถูกขยับ
check.verdicts       # ผลของแต่ละ Agent + เวลาที่ทรัพยากรของตัวเองพร้อม
check.assignment     # ช่วงที่ล็อกได้ (หรือ None พร้อมเหตุผลใน check.result.unscheduled)
check.log            # Negotiation log

day.to_dict(), check.to_dict()   # JSON สำหรับ API / หน้าเว็บ
```

## เงื่อนไขที่โมเดลบังคับ

**Hard:** ห้องไม่ซ้อน (รวมเวลาทำความสะอาด base/infectious) · วัสดุ/รากเทียมพอสำหรับทุกเคส (`supply_items`) · ห้องไม่ถูกใช้ช่วงปิดชั่วคราว (`room_closures`) และสถานะต้องใช้งานได้ · เคส elective อยู่ในเวลา elective ของห้อง · เครื่องมือไม่ถูกใช้ช่วงนัดซ่อม · เตียงพักฟื้นที่ปิดหรือมีผู้ป่วยไม่ถูกจอง · ผู้ป่วยติดเชื้อทางอากาศต้องได้ห้องความดันลบ · บุคลากรไม่ซ้อน · เครื่องมือไม่ซ้อน (รวมเวลาอบ CSSD และ `available_at`) · เตียง PACU/ICU ไม่ซ้อน · อยู่ในกะ (`staff_schedules`) · เกณฑ์ความเหนื่อยล้า: ชม./7 วัน, ชม./วัน, พักหลังเคสดึก (เคสฉุกเฉินเกินได้โดยมีต้นทุนสูงและแจ้งเตือน) · ห้องมี capability ตรง · ทีมมี role/skill ครบ · ทันเส้นตาย (deadline)

**Soft:** ลำดับความสำคัญ EMERGENCY > URGENT > ELECTIVE · ตรงเวลาที่แพทย์ต้องการ · จัดเคสเครื่องมือคล้ายกันติดกัน · ทีมที่เข้าขากัน (`team_synergy`) · กระจายงานให้คนที่เหนื่อยน้อยกว่า · ตอน reschedule เปลี่ยนเวลา/ห้อง/คน/เครื่องมือน้อยที่สุด

เคสที่จัดไม่ได้จะถูกรายงานพร้อมเหตุผล (เช่น ไม่มีห้อง HYBRID, พยาบาล ROBOTIC_CERTIFIED ไม่พอ, ไม่มีช่วงว่าง) และทุกเคสที่จัดได้มีบันทึก "why" ว่ารออะไร ใช้เขียนลง `ai_reasoning_log` ได้

## การจับคู่กับ Schema

| ตาราง | Engine |
|---|---|
| `operating_rooms` | `OperatingRoom` (`room_type` นับเป็น capability ด้วย) |
| `staff` + `staff_schedules` (REGULAR/ON_CALL ที่ `is_available`) | `StaffMember.shifts`, เกณฑ์ `max_hours_per_week/day`, `min_rest_hours` |
| `equipment_units` + `equipment_types` | `EquipmentUnit` (`sterilization_duration_mins`, `available_at`) |
| `recovery_beds` | `RecoveryBed` |
| `surgery_requests` + `procedures` + `surgeon_preference_cards` | `SurgeryCase` |
| `team_synergy` | `team_synergy={(surgeon_id, staff_id): score}` |
| `scheduled_surgeries` + `resource_allocations` | `Assignment` (`cleanup_end_min`, `equipment_ready_min`) |

ค่าที่ schema ยังไม่มีคอลัมน์และ engine ใช้ค่า default: เวลาอยู่เตียงพักฟื้น (PACU 60 นาที / ICU 24 ชม.), เวลาเปิด-ปิดห้อง
